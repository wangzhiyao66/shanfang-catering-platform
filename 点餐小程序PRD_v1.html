一、小程序（顾客端）PRD

面向到店就餐顾客，运行于微信小程序，扫码即用、无需下载。

1.1 产品概述

定位
中餐单店自助点餐入口，替代纸质菜单与服务员记单
目标用户
到店散客、多人聚餐顾客
核心价值
免排队点餐、中餐个性化口味、多人合单、透明订单进度
运行环境
微信小程序（iOS / Android），需微信登录与微信支付

1.2 用户角色

角色特征典型诉求
散客（单人）一人一桌或快速用餐快速找到想吃的、快速下单付款
聚餐多人圆桌/包间，多手机同时点各自选菜、合单结算、分摊口味备注
会员顾客已授权手机号/会员用积分/优惠券、看历史订单、享会员价

1.4 功能详述

F-01 扫码点餐与桌台绑定 P0

功能描述：顾客落座后扫描餐桌二维码，自动进入该门店点餐页并绑定当前桌号，订单直达对应桌台，避免上错菜。支持一桌多人各自扫码、共享同一购物车。

用户故事：「我坐下后扫桌上的码，直接进入菜单，点的菜自动算在我们这桌，不用喊服务员。」

流程：顾客扫码 → 解析桌号/门店 → 进入点餐首页（已绑定桌台）→ 多人可同时加入该桌购物车 → 一人结算。
规则：① 桌码唯一对应一个桌台；② 多人同时点餐时购物车实时合并，最后由任一人统一支付；③ 若扫码失败，支持手动输入桌号；④ 绑定后订单状态推送至该桌顾客与后厨。

F-02 菜品浏览与分类 P0

功能描述：按中餐品类清晰分类展示，支持搜索、销量/价格排序、热门推荐位，售罄菜品自动灰显标注。

默认分类
热菜 / 凉菜 / 汤品 / 主食 / 小吃 / 饮品（可配置）
特色分类
店长推荐 / 热销榜 / 今日特价 / 套餐
筛选
关键词搜索、辣度筛选、价格区间、素/荤
规则：售罄菜品标注「已售罄」且不可加入购物车；分类 Tab 可横向滑动，适配菜品多的中餐场景。

F-03 菜品详情与规格（中餐特色） P0

功能描述：每道菜展示高清图、名称、价格、简介、食材配料、辣度、销量；支持多规格与口味选择，满足中餐个性化需求。

规格-份量
大份 / 小份 / 半份（如「半份¥18·整份¥32」），不同规格不同价
规格-辣度
微辣 / 中辣 / 特辣 / 免辣（川湘菜高频）
忌口备注
预设：免葱 / 免蒜 / 少盐 / 多放醋 + 自由文本输入
称重(可选)
海鲜、烤鸭等按斤/按份计价，选择后自动算金额（P1）
规则：规格选项影响最终单价；同一菜品不同规格在购物车中视为独立条目；忌口备注随订单同步至后厨小票。

F-04 购物车与多人合单 P0

功能描述：菜品加入购物车后可增减数量、删除、填写口味备注，底部常驻显示件数与总金额；同一桌多人点的菜合并展示，由一人统一结算（合单支付）。

流程：选菜→加入购物车→（多人同步合并）→查看已点清单→填备注→去结算→确认桌号/菜品/金额→支付。
规则：购物车按桌台维度聚合；合单支付后整单视为同一笔订单，后厨按桌出单；支持「AA 分账」为远期能力（P2）。

F-05 订单确认与支付 P0

功能描述：支付前展示桌号、菜品明细、规格、备注、总价；支持微信支付，可选会员余额/优惠券抵扣。支付成功后订单实时同步后厨。

规则：① 仅微信支付为必选通道；② 优惠券/会员价在结算页自动计算；③ 支付失败订单进入「待支付」状态可重试；④ 支付成功后向商家后台与后厨推送新订单。

F-06 订单中心：状态 / 催加退 P0

功能描述：顾客可查看当前订单进度（待接单→制作中→已上菜→已完成），支持催菜、加菜、退菜申请，并查看历史订单。

状态流转
待接单 → 制作中 → 已上菜 → 已完成
催菜
一键推送提醒至后厨（限制作中状态）
加菜
在当前桌未结账前可继续加菜下单
退菜
提交退菜申请（口味不符/上错菜），商家后台审核
规则：退菜需商家确认，退款原路返回；加菜视同新子订单但归属同一桌台。

F-07 会员中心 P1

功能描述：微信一键授权成为会员，沉淀积分、等级、储值余额、优惠券；支持收藏常点菜品、查看会员价。

积分
消费累计（如 1 元=1 分），可兑菜品/优惠券/抵现
等级
普通/银卡/金卡，对应折扣或特权（P1）
储值
预充值赠额，快速回笼资金（P1）
优惠券
新人礼、满减券、生日券集中展示与核销

F-08 预约订座与排队 P1

功能描述：顾客在线选择日期、时间、人数、包间需求并提交订座（可付订金锁定）；高峰期支持远程取号、实时查看排队进度与预估等待。

规则：包间数量有限，建议提前预订；订金在到店消费后抵扣；排队临近叫号时微信通知，减少现场聚集。

F-09 外卖 / 自提 P1

功能描述：提供外卖频道与到店自提：设置配送范围/费用/时间，或顾客线上下单选自提时间、到店凭码核销，降低第三方平台抽佣。

规则：外卖与堂食订单在后台分类显示；自提订单显示取餐码；可对接第三方跑腿配送（P2）。

F-10 评价与反馈 P1

功能描述：餐后对菜品口味、上菜速度、服务评分并留言（可附图），商家可回复，形成互动与改进闭环。

二、后端管理系统（商家后台）PRD

面向门店运营者，形态为 PC 网页后台（可配套移动端查看），与小程序、后厨端共用同一后端数据。

2.1 产品概述

使用者
老板 / 店长 / 服务员 / 后厨管理员
核心价值
菜品/订单/会员/数据统一管理，驱动复购与降本
数据关系
与小程序、后厨端实时同步同一份订单/菜品/会员数据

2.2 用户角色与权限

角色权限范围
超级管理员（老板）全部功能：菜品、订单、会员、营销、数据、员工、支付/打印配置、财务对账
店长菜品上下架、订单处理、会员运营、营销活动、查看数据报表
服务员开台/并台/转台、接单确认、标记出餐、桌台状态维护
后厨查看订单、划菜/出餐、退加菜确认（通过 KDS 或后厨屏）

2.3 功能清单概览

模块功能优先级
菜品管理分类/菜品/规格/库存/上下架/推荐爆款P0
桌台管理区域/桌号/容纳人数/状态（空闲·占用·预定·清洁）P0
订单管理接单/出餐/完成/退改、堂食·外卖·预约分类P0
后厨协同分档口打印、KDS 厨显、断网缓存、状态回传P0
会员管理会员资料/等级/储值/积分/优惠券发放P1
营销工具满减/折扣/拼团/秒杀/新人礼/裂变P1
数据报表营业额/订单量/热销榜/翻台率/客单价/复购P1
员工与权限账号、角色、权限分配、操作日志P1
基础设置门店信息/支付配置/打印机配置/营业时间P0

2.4 功能详述

B-01 菜品管理 P0

功能描述：管理菜品全属性：分类、名称、价格、图片、描述、食材、规格（份量/辣度/忌口选项）、库存、上下架、推荐标签。

字段
菜品ID、名称、分类、图片、单价、规格组、库存、是否售罄、推荐位、状态
批量
支持批量导入/导出、批量上下架、批量改价（如节日特价）
规则：库存为 0 自动标售罄并同步小程序；规格改动影响历史订单展示需保留快照；套餐作为特殊菜品（含子菜品组合）。

B-02 桌台管理 P0

功能描述：维护餐厅桌台拓扑：区域（大厅/包间）、桌号、容纳人数、当前状态；支持开台、并台、转台、清台。

状态
空闲 / 占用 / 预定 / 清洁中
二维码
一键生成每桌点餐二维码（印刷或屏显）
规则：占用桌台显示当前订单与就餐人数；并台/转台保持订单归属清晰，防止后厨出单混乱。

B-03 订单管理 P0

功能描述：实时接收新订单并提醒，按堂食/外卖/预约分类；支持接单、标记出餐、完成、退菜/加菜审核、打印小票。

流程：新订单提醒 → 接单（同步后厨）→ 制作 → 标记出餐 → 完成/结账 →（退菜申请→审核→退款）。
规则：订单状态变更实时回传顾客端；退菜需店长/服务员审核；支持订单查询与导出对账。

B-04 后厨协同（打印 / KDS） P0

功能描述：订单自动推送后厨，按档口分单打印（热菜/凉菜/饮品分别出单），可选 KDS 电子厨显；断网时缓存订单、恢复后补打，杜绝漏单。

分档口打印
菜品指定后厨工位，分类出单，减少人工分单
KDS 厨显
按屏制作、超时变色预警、批量划菜（P1）
断网缓存
网络中断暂存订单，恢复自动补打（关键防漏单）
规则：口味备注/忌口完整同步后厨小票；出餐动作由服务员或后厨在屏上确认，状态回传顾客。

B-05 会员管理 P1

功能描述：查看会员资料、消费记录、等级、储值余额、积分；手动/自动发放优惠券，配置会员价与等级权益。

规则：会员数据来自小程序授权（微信 unionId + 手机号）；储值涉及资金，需与支付商户号对账安全。

B-06 营销工具 P1

功能描述：配置优惠券（满减/折扣/代金/菜品兑换）、满减活动、拼团、秒杀、新人礼包、会员日；设置领取条件、门槛、有效期。

规则：活动与小程序端联动，自动核销；避免过度发券，建议结合数据报表评估 ROI。

B-07 数据报表 P1

功能描述：可视化核心经营指标，辅助决策。

指标
营业额、订单量、客单价、热销菜品 Top、翻台率、会员复购率、高峰时段
维度
日 / 周 / 月；按分类、按桌台、按会员

B-08 员工与权限管理 P1

功能描述：创建员工账号、分配角色与权限、查看操作日志（退菜/改账/删单等敏感操作可追溯）。

B-09 基础设置 P0

功能描述：门店信息（名称/地址/营业时间）、微信支付商户配置、打印机绑定与分单规则、桌台二维码生成、消息通知模板。

规则：支付配置错误将导致全店无法收款，需上线前重点校验；打印机配置需与档口分单规则一致。

三、公共非功能性需求

类别要求
性能用餐高峰期（午晚市）支持高并发下单；下单到后厨出单延迟 < 3s；页面加载 < 1.5s
可用性后厨断网时订单本地缓存、恢复后自动补打；核心流程不依赖弱网
安全微信支付走官方通道；用户手机号/支付信息加密存储；后台按角色权限隔离数据
合规小程序需企业主体认证 + 微信支付商户号；用户隐私政策与授权合规
兼容性覆盖 iOS / Android 主流微信版本；后台适配现代 PC 浏览器
扩展性预留外卖对接、多门店、供应链接口，便于后续升级

四、里程碑建议（分阶段落地）

阶段目标范围（小程序 + 后台）
MVP（P0） 跑通堂食点餐闭环 扫码点餐+桌台绑定、菜品分类/规格/忌口、购物车+多人合单、微信支付、订单状态+催加退、后厨分单打印、菜品/桌台/订单/基础设置管理
进阶（P1） 提升复购与客单价 会员积分/等级/储值、优惠券/满减/拼团、套餐、预约订座/排队、外卖自提、评价、数据报表、员工权限、KDS 厨显
远期（P2） 精细化与扩张 外卖对接第三方配送、分销裂变、多门店、供应链进销存、称重计价深化、菜品文化故事
建议：单店起步优先交付 MVP（约 2–4 周，若用 SaaS 则可当天配置上线），验证后再迭代 P1；P2 视经营规模决定。
本 PRD 为 v1 首版，基于前期点餐小程序功能调研整理，供产品规划与选型/开发评估使用。
后续可进入原型设计（UI 草图）与技术方案评估。
