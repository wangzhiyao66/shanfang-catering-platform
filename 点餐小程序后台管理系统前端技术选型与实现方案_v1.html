点餐小程序 · 后台管理系统前端技术选型与实现方案 v1

中餐单店 · 商家 PC 后台（BackendManagement-web）· 与《后端技术选型 v1》《PRD_v1》《数据库设计 v1》契约对齐 · 2026-08-15
结论（推荐栈）： Vue 3 + Vite + TypeScript 作为前端框架， UI 组件库优先 Element Plus（中餐后台表单/表格/权限场景最成熟，与小程序移动端 Vant 视觉自然区分）， 状态 Pinia、路由 Vue Router 4（带 RBAC 守卫）、HTTP Axios（拦截器注入 JWT + X-Shop-Id）、图表 ECharts（数据报表）、实时 WebSocket（订单/KDS 推送）。 与后端 /api/admin 的 JWT 鉴权、{code,data,msg} 返回、401 未登录契约天然对齐。

1. 选型的硬约束（来自已定文档）

  • 后端契约：Java 17 + Spring Boot 3.x，监听 3000；/api/admin/* 用 JWT 鉴权（店长/员工账号密码登录签发），/api/client/* 用 X-Openid/X-Shop-Id。
  • 返回格式：统一 { code:0, data, msg }；401 未登录 / 无 shopId → 触发重新登录。前端 Axios 需按此映射为 Promise resolve/reject（对齐小程序 request.js）。
  • 租户隔离：请求头 X-Shop-Id；后台若支持多店切换，需提供门店切换器并把当前 shopId 注入每个请求。
  • 实时：后厨 KDS / 新订单推送走 WebSocket（后端 /api/kitchen）。后台需 WS 客户端订阅订单流。具体 WS 协议（原生 WS / STOMP / Socket.IO）待与后端确认。
  • 图片：菜品/门店图走 腾讯云 COS，后台上传建议用「后端签发直传 URL + 前端直传」，再回传 URL。
  • 角色：超级管理员(老板)/店长/服务员/后厨 —— 标准 RBAC，权限来自 JWT 中的角色/菜单。

为什么推荐 Element Plus 而非 TDesign：后台是「重表单 + 重表格 + RBAC + 报表」场景，Element Plus 的中文后台模板/组件最全（el-table 虚拟滚动、el-form 校验、el-upload、el-tree 等），出问题好查、招人容易；TDesign 更偏腾讯系设计统一，若未来你想让小程序也换 TDesign 小程序版、追求全栈视觉统一，可再迁。两者都满足「与小程序 Vant 视觉区分」的要求。

3. 与后端契约对齐的关键实现

3.1 请求层（对照小程序 request.js）

// src/utils/request.ts
const service = axios.create({ baseURL: import.meta.env.VITE_API, timeout: 15000 });

// 请求拦截：注入后台 JWT 与租户 shopId
service.interceptors.request.use(cfg => {
  cfg.headers.Authorization = `Bearer ${useUserStore().token}`;
  cfg.headers['X-Shop-Id']   = useShopStore().currentShopId;
  return cfg;
});

// 响应拦截：对齐 { code:0, data, msg }
service.interceptors.response.use(
  res => {
    const { code, data, msg } = res.data;
    if (code === 0) return data;          // resolve(data)
    if (res.status === 401) { /* 跳转登录 */ }
    return Promise.reject(new Error(msg));
  },
  err => { /* 401 -> 登录页；网络错误提示 */ return Promise.reject(err); }
);
开发期在 vite.config.ts 配 server.proxy['/api'] → http://localhost:3000，前端只访问同源 /api，免去 CORS 配置；生产由 Nginx 反代。

3.2 RBAC 权限模型

  • 登录：POST /api/admin/auth/login → 返回 JWT（含角色/菜单）；前端存 Pinia + localStorage。
  • 路由守卫：全局 beforeEach 校验 token；未登录跳登录页；已登录按角色动态注册路由（后端下发的菜单映射为路由表）。
  • 按钮级权限：自定义指令 v-permission="'order:refund'"，无权限隐藏/禁用按钮（退菜/改账等敏感操作）。
  • 操作日志：敏感动作（删单/退菜/改账）调用后端 operation_log 落库，前端仅触发。

3.3 图片上传（COS 直传）

// 1) 前端请求后端签发直传 URL： POST /api/admin/upload/cos-sign
// 2) 用该 URL + 表单(含 signature/key) 直传腾讯云 COS

密钥只存后端，前端拿「临时直传凭证」即可，符合安全约定（密钥不下发前端）。

3.4 实时推送（订单 / KDS）

  • 建立 WS 连接订阅本店订单流；新订单 → 订单管理页高亮 + 声音/桌面提醒（B-03）。
  • 后厨协同（B-04）可与 KDS 同屏或独立路由：接单→分档口→出餐→状态回传顾客端，断网由后端兜底缓存。
  • WS 鉴权用同一 JWT；重连/心跳需前端封装。协议细节（原生 WS / STOMP / Socket.IO）待与后端确认。
